    Quickstart

    Install the CLI, authenticate with GitHub, and push your static build. Every merge to main publishes automatically. 

    import { deploy } from '@pages/cli';

deploy({
  source: './dist',
  branch: 'gh-pages',
});

    from pages import deploy

deploy(
    source="./site",
    branch="gh-pages",
)

    $ npm install -g pages-cli
$ pages login
$ pages deploy
    Tip: Automate docs previews with pull request environments.

    Platform features

    The parts that are not layout.

    Everything above is markup and CSS. These panels exercise the browser and hosting features that make a static site behave like an application — each one live on this page, not described in the abstract.

    Installable and offline

    A web app manifest plus a service worker turn this page into an installable app that works with the network off. Both are static files; the only requirement is HTTPS, which Pages provides on *.github.io and custom domains alike.

    Client-side routing

    Pages has no rewrite rules, so a deep link into a single-page app would normally 404 on refresh. The fix is a 404.html that hands the path back to the app through a query string.

    • Real URLs via the History API, no hash routing.
    • Deep links survive a hard refresh.
    • Back and forward buttons behave normally.
    Open the routing demo

    Redirects, such as they are

    There is no way to send a 301 from a static host. A meta refresh plus a canonical link is the whole toolkit — and it is exactly what the jekyll-redirect-from plugin generates for you.

    Syndication needs no server either. These are three static documents that Pages serves verbatim; on a Jekyll build the jekyll-feed and jekyll-sitemap plugins generate them from your posts.

    Get started

    Ready to remix these patterns?

    Clone the repository, customize the sections you need, and publish straight to GitHub Pages. Pair this with Actions workflows to automate builds from your favorite framework.

    1. Fork or clone. Duplicate this playground into your own GitHub account.
    2. Edit the content. Replace copy, imagery, and components with your brand.
    3. Publish. Push to main or a gh-pages branch and flip the GitHub Pages switch.
